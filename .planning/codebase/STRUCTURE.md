## Directory Purposes

**`cinatra/`:**
- Purpose: Platform sidecar directory; holds all files the Cinatra marketplace and runtime consume
- Contains: `oas.json` (agent flow spec for `kind: "agent"` extensions); would hold `workflow.bpmn` for workflow extensions
- Key files: `cinatra/oas.json`

**`.github/workflows/`:**
- Purpose: GitHub Actions CI/CD pipelines
- Contains: `ci.yml` (build + kind-gate on push/PR), `release.yml` (marketplace publish on GitHub Release)
- Key files: `.github/workflows/ci.yml`, `.github/workflows/release.yml`

**`.planning/codebase/`:**
- Purpose: GSD codebase map output — machine-readable architecture and structure docs for planning tools
- Generated: Yes (by GSD mapper)
- Committed: Yes

## Key File Locations

**Agent Spec (entry point for the platform):**
- `cinatra/oas.json`: Full declarative flow graph — nodes, edges, I/O schemas, renderer references

**CI Gate (standalone validator):**
- `extension-kind-gate.mjs`: Zero-dependency Node.js script run by CI and exportable as a library

**Extension Manifest:**
- `package.json`: Package name, version, `cinatra.kind`, `cinatra.apiVersion`, `cinatra.dependencies`

**CI Pipelines:**
- `.github/workflows/ci.yml`: Build + typecheck + test + pack dry-run + agent OAS gate
- `.github/workflows/release.yml`: Thin caller for the org reusable marketplace-release workflow

**Documentation:**
- `README.md`: Capabilities overview for end users / marketplace listing

## Naming Conventions

**Files:**
- Cinatra sidecar: `cinatra/oas.json` (agent) or `cinatra/workflow.bpmn` (workflow) — fixed names required by the platform
- Gate script: `extension-kind-gate.mjs` — kebab-case, `.mjs` extension for ESM
- CI workflows: `ci.yml`, `release.yml` — kebab-case `.yml`

**Directories:**
- Platform sidecar dir: always `cinatra/` (lowercase, fixed name)
- GitHub workflows: always `.github/workflows/` (GitHub convention)

**OAS identifiers:**
- Component `id` values: `kebab-case` (e.g., `"skill-recommender-flow"`, `"recommend_gate"`)
- Node names: Title-case human labels (e.g., `"Review skills"`, `"Inputs"`)
- Edge names: `snake_case` describing the connection (e.g., `"start_to_recommend_gate"`)

## Where to Add New Code

**New agent flow node:**
- Add to `cinatra/oas.json` under `nodes`, `$referenced_components`, and the appropriate `control_flow_connections` / `data_flow_connections` arrays

**New agent input or output:**
- Add to `cinatra/oas.json` top-level `inputs`/`outputs` arrays and wire via `DataFlowEdge` to the relevant node

**New CI validation rule (banned primitive, etc.):**
- Add to `extension-kind-gate.mjs` — update `BANNED_PRIMITIVES` or `BANNED_TYPEHINTS` arrays, or add a new scan function following the existing pure-function pattern

**New kind-specific gate:**
- Add an exported `validateXxx(packageRoot)` function in `extension-kind-gate.mjs` and dispatch it from `runGate()` for the new `cinatra.kind` value

**Documentation:**
- User-facing: `README.md`
- Architecture/planning: `.planning/codebase/`
